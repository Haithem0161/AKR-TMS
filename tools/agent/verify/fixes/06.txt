### 7.N The masked deny tag (V-06-06-a, V-06-06-b, MEDIUM; DR-413)
Section 3.2 step 6 names two deny tags. From phase 06 on the policies use a third, `@deny("masked")`, on a `forbid` that hides a record by an attribute other than a branch, pool or tier test (a restricted scenario, a policy pack outside its readers, a report outside its case team). A determining forbid with this tag is classified `DenyReason::Masked`, a new variant for which `masks` returns true whatever the resource kind: the answer is the 404 `E_NOT_FOUND` body of a missing record, and the access event is the `deny` of section 3.6. The kind need not be in `MASKED_KINDS`. A list route that can return such rows filters them in SQL by the same predicate (section 3.6, lists), and the phase that writes the forbid tests the 404.
Every other tag (`self_approval`, `state`, `aal` and the like) names the reason of a `Forbidden` deny; its problem code is the one the phase that writes the policy gives.
@@ END

The cursor of the `common` module (section 2) is the type `Keyset`: an opaque position on a list's sort columns, sent as the `cursor` query parameter and returned as `next_cursor`, as the pagination rule of docs/API.md states. `Page<T> { items: Vec<T>, next: Option<Keyset> }` is what every keyset list method returns; `next` is `None` on the last page. `Cursor` in the repository signatures of phases 03 and 04 is the same type.
