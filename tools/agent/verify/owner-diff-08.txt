+### 7.10 The four source labels of a Latin name (owner decision 9; DR-420)
+The owner's decision: the labels `card`, `passport`, `typed` and `generated` of DESIGN-SYSTEM 7.6 are all used. This block replaces the label rule of section 7.9; the rest of section 7.9 stands (which row is the original, which is the transliteration, and no second line when the party has no Latin row).
+
+1. **Data.** Each name row that the API returns carries `capture_source` (phase 10 section 7.26): `card`, `passport`, `typed` or `generated`. The bank's mapping sets it; a name with no stated source is `typed`.
+2. **Component.** `Name` takes `latin?: { text: string; source: 'card' | 'passport' | 'typed' | 'generated' }`. The source label is shown after the Latin line, in the muted small style of DESIGN-SYSTEM 7.6, as a word and never as an icon or a colour alone. The label is shown for the Latin line only; the original line has none.
+3. **Words** (`src/i18n/locales/{ar,en}/enums.json`, keys `name_source.<value>`):
+
+| Key | Arabic | English |
+|-|-|-|
+| `name_source.card` | من البطاقة الوطنية | from the national card |
+| `name_source.passport` | من جواز السفر | from the passport |
+| `name_source.typed` | أُدخل يدوياً | typed |
+| `name_source.generated` | مولَّد آلياً | generated |
+
+4. **What does not change.** The product still generates no Latin form and reads no document: `generated` is shown only when the bank's mapping says that a program of the bank produced the name. Phase 14's back-transliteration serves matching only and is never shown under a name.
+5. **Tests** (added to the `Name` row of section 3.7): the component renders each of the four labels in both languages from a fixture; a fixture with no `latin` renders one line; the mixed-script order probe of section 3.7 passes with a label present.

+### 7.11 The panel Bank cases on E1p (owner decision 2; DR-415)
+Phase 07 section 7.6 lets the bank add its own cases to the goAML regression corpus. E1p shows them and takes the proposals. This block adds one panel to a screen this phase already builds; it adds no screen, no route and no rail entry.
+
+1. **Where.** E1p (`/goaml-check/profiles`) gains the panel **Bank cases** under the version list, read with `getGoamlCorpusCases` for the profile code shown. A2, M, CFG and CHK see it (the roles of E1p). The actions of items 3 and 4 are rendered for A2 and M only; CFG and CHK read.
+2. **List.** A `DataTable`: the key, the expected result in words ("Would be rejected" with its rule codes, or "Accepted"), the state word, the last intake result in words, and the date added; a state filter. There is no file column and no download: the API returns no file.
+3. **Add a case** (A2, M). A form: `FileDrop` limited to one XML file; the key (lower-case letters, digits and hyphens, 3 to 61 characters); the expected outcome (two choices, "Would be rejected" and "Accepted"); the expected block codes, a multi-select over the rule codes of the active version, enabled only with "Would be rejected"; an optional Office message code, a select over the active version's rejection patterns; and the reason code and reason text of the propose form. Above the submit button stands the notice "The file is masked before it is kept: names, numbers and text are replaced. The original is deleted." in the user's language. Submit sends `postGoamlCorpusCases` (multipart) with a generated `Idempotency-Key`; on 202 the page links to the change request on G10. A 422 shows the field message for `file_too_large`, `type_not_allowed`, `case_key_taken`, `expectation_invalid`, `rule_unknown` or `too_many_cases`.
+4. **Retire** (A2, M), on an `active` row: a confirm dialog with the reason code and text, then `postGoamlCorpusCasesIdRetire`; on 202 the link to the change request.
+5. **Words** (`src/i18n/locales/{ar,en}/enums.json`):
+
+| Key | Arabic | English |
+|-|-|-|
+| `corpus_case.state.proposed` | مقترحة | Proposed |
+| `corpus_case.state.active` | فعّالة | Active |

+| `corpus_case.state.rejected` | مرفوضة | Rejected |
+| `corpus_case.intake.pending` | بانتظار الفحص | Waiting for the check |
+| `corpus_case.intake.met` | تطابق النتيجة المتوقعة | Meets the expectation |
+| `corpus_case.intake.not_met` | لا تطابق النتيجة المتوقعة | Does not meet the expectation |
+| `corpus_case.intake.unsafe_file` | تعذّر الفحص: ملف غير آمن | Could not be checked: unsafe file |
