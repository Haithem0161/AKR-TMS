- Target: phase-14.md section 3.2 (`list_activate`), section 4.2 (timers), new section 7.10.
- Check: `grep -n -i -E "one hour|1 hour|60 min" docs/plan/phase-14.md` returns no match on a re-screen clock. `grep -n "Timers" -A1 docs/plan/phase-14.md` shows only `screening_alert_clock`. The look-back job `screening_lookback` (phase-14.md:1209, queued by `list_activate`) has no timer and no deadline. The 12-hour freshness alarm is built (phase-14.md:936, CHECK on line 85), so only the one-hour part is missing. `grep -n "finished_at" docs/plan/phase-14.md` shows the run's end column is `finished_at` (not `completed_at`); `degraded_flags` exists (phase-14.md:239).
- Proposed 7.x text: "### 7.10 One-hour re-screen clock after list activation (ROADMAP M9 exit criterion; VC-03)"
  1. Add the timer kind `list_rescreen_clock` (owner kind `list_version`, owner id = the version id). `ListRepository::activate` schedules it in the same transaction as the activation, with `fire_at = activated_at + interval '1 hour'`. This is elapsed time, not the business clock (`BusinessClock` is not used).
  2. When the `screening_lookback` run for that version writes `finished_at` (section 1.2 `alert.screening_runs`), the same transaction calls `TimerService::cancel_for_owner(list_version, id, list_rescreen_clock)` and writes audit `list.rescreen_completed {list_id, version_id, seconds}` (ids and a number only).
  3. When the timer fires and no finished look-back run exists for the version, write audit `list.rescreen_late {list_id, version_id}` once, raise the metric `akr_list_rescreen_late{list}`, and add the flag `rescreen_late` to `degraded_flags` of every run started until the look-back finishes (the same mechanism as `list_stale`, section 3.2).
  4. The one-hour value is a fixed constant in code, not a setting. The 12-hour freshness rule of section 3.2 is unchanged.
  5. The S3 list status screen shows the last `list.rescreen_completed` duration next to the list lag already reported in section 3.9.
  Owner of the new audit names: phase 14 section 3.13. Add the two audit names and the timer kind to the phase 14 section 3.13 and 4.2 lists when applied.
